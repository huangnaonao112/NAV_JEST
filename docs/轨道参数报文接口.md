# 轨道参数报文接口（$ORB）

> 适用版本：2026-11-03 起
>
> 相关代码：`src/models/OrbitMessage.h/.cpp`（解析）、`SatelliteModel::applyOrbitFrame`（渲染）、
> `src/RackStatusClient.cpp`（分发）

---

## 1. 职责边界（重要）

```
┌────────────────────┐   $ORB（开普勒根数）   ┌──────────────────────┐
│ 外部解算器           │ ───────────────────▶ │ 本仿真软件             │
│ · 广播星历/RINEX 解析 │                      │ · 报文解析             │
│ · 选星（高度角/健康）  │                      │ · 二体推进/3D 轨道渲染  │
│ · 根数归一/历元统一    │                      │ · 星下点 → 2D 地图      │
└────────────────────┘                       └──────────────────────┘
```

**本项目不解析星历文件**（RINEX/BRDC 等）。星历解析、精密定轨、选星属于外部解算器，
本项目只接收"已经算好的开普勒根数"，并把它们变成 3D 轨道和 2D 星下点。

这样做的收益：
- 仿真软件的职责单一：只做"报文 → 可视化"，换星历源/换解算算法不影响本项目；
- 报文层可测试、可回放、可伪造，便于联调和验收；
- 3D 与 2D 使用**同一套解算结果**，天然一一对应。

---

## 2. 外部解算器需要提供哪些参数

对每颗卫星，只需要**七个量 + 一个历元**（广播星历里都有，二次谐波改正项
`Cuc/Cus/Crc/Crs/Cic/Cis` 对显示无意义，可丢弃）：

| 参数 | 符号 | 单位 | 说明 |
|---|---|---|---|
| 半长轴 | a | km | 由 √a 平方换算：`a = (sqrtA/1000)²` 若原始是 √m |
| 偏心率 | e | — | 0 ~ 0.9 |
| 轨道倾角 | i | deg | 0 ~ 180 |
| 升交点赤经 | Ω | deg | 惯性系 |
| 近地点幅角 | ω | deg | |
| 参考平近点角 | M0 | deg | **参考历元**处的平近点角 |
| 平均角速度 | n | rev/day | 可填 0，渲染侧按 `n = √(μ/a³)` 推算 |
| 历元 | week, tow | GPS 周 / 周内秒 | 所有卫星共用一个历元 |

> 若外部解算器输出的是"某时刻的 ECEF 位置/速度"，请先转成根数再发；
> 本项目不做定轨反算（保持职责单一）。

**选星建议**：按接收机位置与 10° 截止高度角筛选，单 GPS 约 8~12 颗，
GPS+BDS+Galileo 合计 25~35 颗——这就是"正常定位能观测到 30 多颗"的来源。

## 3. 报文格式

NMEA 风格，一行一帧，以 `\n` 结尾；`*` 后为校验和（本项目不校验，保留兼容）：

```
$ORB,HHMMSS.mmm,week,tow,count,
     PRN,sys,a,e,i,raan,argp,M0,n,health,
     PRN,sys,a,e,i,raan,argp,M0,n,health,
     ...（共 count 组）
*CS
```

| 字段 | 类型 | 说明 |
|---|---|---|
| HHMMSS.mmm | 时间 | 仅日志用，不参与解算 |
| week | int | GPS 周（BDS 周 +1356 归一；Galileo 直接用 GPS 周） |
| tow | double | 周内秒 0~604800 |
| count | int | 卫星数 1~128 |
| PRN | int | 系统内编号 1~64 |
| sys | char | `G` / `C` / `E` |
| a | double | 半长轴 km，合法范围 6000~60000 |
| e | double | 偏心率 0~0.9 |
| i | double | 倾角 deg 0~180 |
| raan | double | 升交点赤经 deg |
| argp | double | 近地点幅角 deg |
| M0 | double | 参考平近点角 deg |
| n | double | rev/day，0 表示由 a 推算 |
| health | int | 0 健康 / 非 0 灰显 |

**示例（3 颗星）**：
```
$ORB,120000.000,2309,259200.000,3,1,G,26560.123,0.013000000,55.000000,120.000000,0.000000,45.000000,2.00570000,0,7,C,42164.000,0.000400000,3.000000,60.000000,180.000000,120.000000,1.00270000,0,11,E,29600.000,0.000200000,56.000000,200.000000,0.000000,10.000000,1.70450000,0*3C
```

**发送频率**：
- 轨道根数变化很慢（广播星历 2 h 更新一次），建议 **5~30 s 重发一次**用于兜底；
- 同一帧重复发送是幂等的（历元不变，渲染侧按历元推进，不会跳变）；
- 若外部解算器切换了历元（新星历），重新发送即可，渲染侧会以新历元重新起算。

## 4. 渲染侧语义

| 环节 | 实现 |
|---|---|
| 卫星位置 | 从历元起按二体开普勒推进：`propagateKepler(elements, t - t0)` |
| 3D 轨道环 | 在**惯性系**采样一个完整周期（96 段），闭合椭圆；不在地固系采样，否则环不闭合 |
| 星下点 | 惯性推进位置绕 Z 转 `-Ωe·tow` → ECEF → WGS-84 大地坐标（见 §10.1） |
| 2D 地图 | 星下点以 1 Hz 写入 `PntDataModel`，与 3D 同源 |
| 配色 | GPS 蓝 `#3B82F6`、北斗橙 `#F59E0B`、Galileo 紫 `#A78BFA`、不健康灰 `#8A8A8A` |
| 轨道显示面板 | 真实模式下列表开关不生效（卫星按系统统一显示） |

**为什么 3D 用惯性系、2D 用大地坐标**：场景中的地球是静止的，轨道若在地固系采样会
变成不闭合的弧段；惯性系闭环更符合"轨道"的视觉语义。两者由同一状态向量导出，
同一时刻的 3D 位置与 2D 星下点是严格对应的。

## 5. 误差与适用范围

- 模型为**二体开普勒**，不含 J2 等摄动：24 h 内位置误差约数十公里，
  对"轨道示意 + 星下点展示"足够；若要精确对星，需要外部解算器提高重发频率
  （例如每分钟一帧，直接用新根数刷新）。
- 星历本身有效期约 2 h；超过后误差增大，应由外部解算器切换新星历。
- 健康字非 0 的卫星仍会显示（灰色），便于现场定位问题；不希望显示时外部解算器不发即可。

## 6. 与既有报文的关系

| 报文 | 作用 | 与 $ORB 同时存在时 |
|---|---|---|
| `$SAT` | 设备上报的星下点（2D 用） | `$ORB` 模式下以解算星下点为准（1 Hz 覆盖） |
| `$PNT`/`$JAM`/`$DUT`/`$MNT`/`$TRJ` | 其它遥测 | 互不影响 |
| `$END` | 清场 | 退出真实轨道模式，清空卫星与轨道环 |

## 7. 自检与排障

| 现象 | 排查 |
|---|---|
| 日志无 `[ORB] received` | 检查连接/端口；确认帧以 `\n` 结尾；确认 payload 以 `ORB,` 开头 |
| 有 `received` 但 3D 无卫星 | 看 `[ORB] subpoints synced` 是否出现；检查面板是否处于真实模式 |
| 卫星位置明显不对 | 核对 a 的单位（km 而非 m）、角度是否 deg、周数是否归一到 GPS 周 |
| 3D 与 2D 对不上 | 两者必须来自同一帧；检查是否混入了设备 `$SAT` 数据 |

日志位置：`build/cmake/Release/logs/scene_debug.log`，关键字 `[ORB]`。

## 8. 一天报文回放（文件驱动）

### 8.1 文件格式

与设备报文一致的 NMEA 风格文本，一天 = 1440 帧（每分钟一帧）：

```
$BEG,00000.000,2*5C                       ← 开始任务
$ORB,000000.000,2309,0.000,97,...         ← 00:00 的星座（97 颗 = 全天并集）
$ORB,000060.000,2309,60.000,97,...        ← 00:01
...
$ORB,235900.000,2309,86340.000,97,...     ← 23:59
$END,86399.000,2*5E                       ← 结束清场
```

**health 字段语义扩展**（仅 $ORB）：
- `0` = 该分钟这颗卫星参与定位（正常色显示）
- `1` = 该分钟不参与（低于截止高度角，灰显）

每帧固定发"全天并集"（97 颗），集合不变 → 渲染端全程走快路径，
卫星集合从不重建。这是性能的关键（见 8.4）。

### 8.2 生成（外部解算器角色）

```bash
# 全量：1440 帧，约 11.5 MB
python scripts/orb_day_generator.py --brdc BRDC00IGS_R_20241000000_01D_MN.rnx \
    --out playback/orb_day_full.txt

# 抽稀：每 5 分钟一帧（288 帧，约 2.3 MB）
python scripts/orb_day_generator.py --brdc ... --stride 5 --out playback/orb_day_5min.txt

# 自定义接收站与截止角
python scripts/orb_day_generator.py --brdc ... --lat 30.0 --lon 114.0 --mask 15
```

生成逻辑：解析广播星历 → 逐分钟计算每颗卫星对接收站的仰角 →
≥ mask 记入该分钟可见集 → 全天可见集取并集作为固定星座 →
每帧把各星的 M0 推进到该分钟历元。

仓库内已带样本：`playback/orb_day_full.txt`（北京站，2024-04-09，
真实 IGS BRDC）、`playback/orb_day_5min.txt`（5 分钟抽稀版）。

### 8.3 回放

```bash
# 一天的量 150 秒播完（约 576 倍速）
python scripts/orb_file_player.py --file playback/orb_day_full.txt --seconds 150

# 抽稀版 60 秒，循环 3 遍
python scripts/orb_file_player.py --file playback/orb_day_5min.txt --seconds 60 --loop 3
```

回放器本机监听 8000（软件自动重连），按目标时长匀速发帧。
建议**先启动回放器再启动软件**（避免残留监听抢占端口）。

### 8.4 渲染端的关键设计

| 设计 | 原因 |
|---|---|
| 固定集合（全天并集）+ health 编码可见性 | 若按分钟只发可见星，集合频繁增删 → 每次 QML 全量重建 + 38 个轨道环重采样（实测掉到 38 fps、149 ms 卡顿）；固定集合后全程快路径，**180 fps / 10-13 ms** |
| 日速率快进（`m_dayRate`） | 相邻帧代表相差 60 s 的日时间；若按真实秒推进，卫星每帧跳 12 分钟位置（MEO 一步 2600 km）。渲染端从相邻两帧自动推算倍率（150 s 播一天 ≈ 576×），帧间沿开普勒弧连续快进，肉眼是平滑的"一天延时摄影" |
| 快路径只更新 M0/颜色 | 轨道环是整周期采样，形状与 M0 无关；BRDC 单文件内 a/e/i/Ω/ω 不变 → 环全程零重建 |

### 8.5 实测（北京站，真实 BRDC 2024-04-09）

| 项目 | 值 |
|---|---|
| 全天并集 | 97 颗（GPS+北斗+Galileo） |
| 每分钟参与定位 | 24~52 颗（平均 38.3） |
| 全量 1440 帧回放 150 s | fps 180 稳定，maxGap 10-13 ms |
| 抽稀 288 帧回放 60 s | 同上 |
| `$END` 清场 | 轨道/卫星/2D 全部消失 |

## 9. 只显示参与定位的卫星（2026-11-03 更新）

### 9.1 显示语义

- health=0（该分钟参与定位）：显示卫星本体 + 轨道环 + 2D 星下点
- health≠0（低于截止角/不参与）：**全部隐藏**（不是灰显）
- 每分钟帧切换时可见集合随之轮换（日志 `subpoints synced: XX sats` 实时反映）

### 9.2 零重建实现（性能关键）

固定集合（全天并集）不变，只切换"显示/隐藏"：

| 对象 | 机制 | 代价 |
|---|---|---|
| 卫星本体 | delegate `visible` 绑定 `isSatelliteVisible(index)`，引用 `visibilityEpoch`（health 翻转时 ++ 并发信号） | 单 delegate 属性翻转，零重建 |
| 轨道环 | 同一绑定机制（环 delegate 同样引用 epoch） | 零重建 |
| 2D 星下点 | `syncSubpointsToPnt` 过滤 `visible` | 1 Hz 重发小列表 |

QML 绑定技巧：`Q_INVOKABLE` 调用本身不是响应式的，绑定中同时引用
`visibilityEpoch` 属性使其在翻转时重估——整个 Repeater 不重建。

### 9.3 3D 采用地固系（ECEF）渲染

卫星位置与轨道环最终都在 **ECEF** 显示（此前为 ECI）：

- ECI 下卫星随 GMST 相对固定地球漂移，"参与定位的卫星"不会聚在接收站一侧，
  3D 与 2D 无法视觉对应；
- ECEF 下卫星始终挂在接收站半球，与 2D 星下点严格同源；
- 实现与语义已在 2026-11-04 升级（帧锚点、逐帧 health、展示参照系开关），
  见 §10；本节保留历史结论（地固系下卫星聚在接收站半球）。

### 9.4 线宽调整

ECEF 环的近段可逼近相机（相机位于轨道球面内部），线宽过粗会变成巨带：

- `ORBIT_THICKNESS_KM` 40 → 25，欺骗环 70 → 45
- `lineWidthScale` 上限 4.0 → 1.5
- 真实模式卫星模型 `visualScale` 1.5 → 1.0（缓解贴脸）

### 9.5 已知视觉限制

- 轨道环近段（穿过相机球面时）仍会显得较粗——世界空间线宽的固有限制。
  彻底解决需屏幕空间线宽着色器（见坐标系文档 7.4，待有硬需求再做）；
- GEO/IGSO 环半径大于默认相机距离，回放中环会从相机旁掠过，属预期行为。

## 10. 卫星符号尺寸设计（2026-11-03）

### 10.1 问题

卫星是**符号化标记**（真实卫星 ~10 m，按真实尺寸不可见）。固定 scale 下
透视导致：同一画面内近轨卫星巨大、GEO 远端几乎不可见（差 10 倍+）；
近掠过相机时贴脸霸屏。

### 10.2 设计：距离部分补偿（屏幕准恒定）

```
distScale = clamp( (camDist / MARKER_REF_DISTANCE_KM) ^ MARKER_SCALE_EXPONENT,
                   MARKER_SCALE_MIN, MARKER_SCALE_MAX )
最终 scale = 基础 visualScale × distScale
```

常量（`CoordinateSystem`，QML 经 `CoordinateSystem.marker*` 访问）：

| 常量 | 值 | 含义 |
|---|---|---|
| `MARKER_REF_DISTANCE_KM` | 26000 | 参考距离（MEO 轨道半径，distScale=1 的基准点） |
| `MARKER_SCALE_EXPONENT` | 0.75 | 补偿指数：<1 保留少量深度感；=1 全补偿（全部同大无层次） |
| `MARKER_SCALE_MIN` | 0.25 | 近掠过下限（防贴脸） |
| `MARKER_SCALE_MAX` | 2.0 | 拉远上限（防符号相对地球过大） |

指数 0.75 的效果（屏幕视角 ≈ scale/dist）：
- 同一画面内 GEO 远端与 MEO 远端表观大小差 <5%（原 10 倍+）；
- 近掠过被下限钳住；拉远/拉近时表观大小基本恒定（±25% 内）；
- 保留 25% 的近大远小，不丢失深度感。

### 10.3 实现位置

纯 QML（`SatelliteInstancer.qml`），零 C++ 改动、零模型重建：

```qml
readonly property real camDist: ...   // 相机 scenePosition 到卫星 scenePosition
readonly property real distScale: clamp(...)
scale: baseVisualScale * distScale
```

相机引用由 `SceneViewItem` 注入（`sceneCamera: camera`）。绑定随相机拖动/
卫星运动自动逐帧重估（97 个轻量属性更新/帧，180 fps 无感）。

### 10.4 实测（全天回放）

| 相机距离 | 卫星表观尺寸 | 相对地球 |
|---|---|---|
| 15000（拉近） | 不贴脸（下限 0.25 生效） | — |
| 30000（默认） | ~30 px | 合适 |
| 60000（拉远） | ~35-40 px | 比例协调 |

配套调整：真实模式基础 `visualScale` 1.0 → 0.7（原 1.0 符号偏大）。

## 11. 3D/2D 一致性链路（2026-11-03 定稿）

### 11.1 最终数据流

```
$ORB 根数(Ω0 等已吸收 GMST 偏置, 输出语义 = ECEF)
  → 二体推进 propagateKepler(el, elapsed)     [帧时刻精确, 帧间外推]
  → 外推期绕地轴(Z)转 -Ωe×tow_render          [补地球自转, 见 11.3]
  → 场景轴映射 scene=(y,z,x)                   [λ=0→+Z, Y=北极, 与地球贴图一致]
  → 3D 渲染(卫星+轨道环)
  → 星下点 = ecefToGeodetic(同一 ECEF)         [数据面用标准轴序]
  → 1Hz 写 PntDataModel → 2D 地图标记
```

**3D 与 2D 来自同一个 ECEF 向量**——严格一一对应。

### 11.2 本次修复的三层 bug（复盘）

| 层 | bug | 症状 |
|---|---|---|
| 生成器 | 仰角筛选对广播 ECEF 又做了一次 GMST 旋转（双转） | "北京可见集"错位 ~105°，标记散布全球 |
| 渲染-外推 | dayRate 由 TCP 到达间隔瞬时推算，突发下乱跳 | 外推位置过冲（GEO 偏 39°） |
| 渲染-约定 | ① 把广播 Ω0 当"纯惯性根数"再做 GMST 旋转（重复扣自转，错 196°）；② 场景轴映射后星下点误用场景序喂标准 ecefToGeodetic | GEO 定点漂移/纬经度全错 |

**检验基准**（修好后）：5 颗 BDS GEO 全天钉在定点——C01=144.3E、C02=84.1E、
C03=110.5E、C04=159.9E、C05=58.9E（与真实定点 140/80/110.5/160/58.6E 一致，
残差为缺 GEO -5° 倾角特殊旋转的米级-度级近似误差，文档 §5 已述）。

### 11.3 关键实现点

- **帧时刻**：`propagateKepler(el, 0)` 的输出直接当 ECEF 用（帧根数语义即 ECEF）；
- **帧间外推**：先惯性推进 `elapsed = (wall-Δ)×dayRate`，再绕地轴转
  `-Ωe×tow_render`（tow_render = 帧 tow + elapsed）——GEO 净转≈0（定点不动）、
  MEO 净转 (n-Ωe)·Δ ✓；
- **dayRate**：EMA 平滑 + [×0.25, ×4] 限幅，外推总量钳制 ≤2 帧日时间；
- **回放文件含 $PNT**（接收站=模拟源），2D 地图 `locateToSimPoint()` 可直接
  定位到接收站；新增 `Map2DView.locateTo(lon, lat, zoom)` 通用定位入口。

### 11.4 验证

- 2D 截图：标记聚在以北京为中心的区域（C/G/E 分色）✓
- GEO 定点全天稳定 ✓；`subpoints synced n=47~50` 每秒刷新 ✓
- `SceneLogger` 现已注册为 QML 单例（`SceneLogger.logQml(cat, msg)` 可从
  QML 直接写场景日志，`MAP2D` 类别示例）

## 12. 对接交接清单（外部解算器 ↔ 本软件）

### 12.1 解算器侧需要交付/确认的

## 13. 登录与本地应急账号（2026-11-03）

登录验证顺序：**本地应急账号 → 数据库账号**。

| 路径 | 条件 | 响应 |
|---|---|---|
| 本地 | `config.json` 的 `local_account` 启用且账号/哈希匹配 | `{"ok":true,"source":"local"}` |
| 数据库 | `tb_userinfo` 匹配 | `{"ok":true,"source":"db"}` |
| 失败(DB 无数据) | 多半 DB 掉线/迁移 | 提示"可使用本地应急账号" |

设计要点：
- 本地账号与数据库完全无关——改库/迁移/掉线时不会被锁在门外；
- 密码只存哈希（与 DB 侧同一 `PasswordHasher` 格式 `salt$hash`）；
- `enabled` 为 JSON 布尔；未配置节 = 默认启用（用户名 admin 需配哈希才可用）；
- 登录日志区分来源（`LOGIN user=xxx source=local|db`）。

## 14. $DSP 欺骗干扰报文（2026-11-04）

干扰演示完全报文驱动（轨道显示面板已删除）。

```
$DSP,HHMMSS.mmm,count,idx,a,e,i,raan,argp,M0,active[,...]
```

| 字段 | 说明 |
|---|---|
| idx | 欺骗源编号 1~16（同 idx 再次声明 = 更新位置/状态） |
| a | 半长轴 km（100~60000） |
| e / i / raan / argp / M0 | 开普勒根数，与 $ORB 同语义（M0+n·tow 即 ECEF） |
| active | 1=欺骗卫星显示+干扰波束开；0=隐藏 |

语义：
- **全量声明式**：帧中未出现的欺骗源自动移除；
- **欺骗星沿轨道连续运动**：帧间由本软件按二体推进（与 $ORB 星座同一引擎），
  波束/动画随卫星移动——不需要解算器高频发帧；
- 欺骗星独立于 $ORB 星座（追加管理），$ORB 帧不冲掉欺骗源；
- 欺骗源不上 2D 星下点（它们不是定位卫星）。

演示（full_demo.txt 幕一）：欺骗源 1 = 克隆定位 MEO（升交点 +8°，平行轨道），
欺骗源 2 = 克隆高轨星（升交点 -10°）；09:00-13:00 active=1（干扰窗口），
其余时刻 active=0。随 $SAT 每帧更新 M0——欺骗星与定位星座同步运动。

## 10. 时间基准、帧锚点与展示参照系（2026-11-04 更新）

### 10.1 广播语义与地球自转（-Ωe·tow）

广播根数的 Ω0 对齐"周起始惯性系"：惯性推进位置绕 Z 转 `-Ωe·tow_render`
（tow_render = 帧 tow + 日时间外推）才是 ECEF。**不能**再做 GMST 旋转
（重复扣地球自转，曾致星下点错位 196°）。验证：GEO 帧时刻定点不动；
MEO 净转 (n-Ωe)Δ。

生成器侧同一约定的实现：`scripts/orb_common.py::sub_ecef`（简化二体 +
-Ωe·tow）。**修改坐标约定必须同时改 C++ 与 orb_common 并跑金标测试**。

### 10.2 逐星帧锚点（修"欺骗卫星左右闪动"）

快照内 `$ORB`（重置全局 tow 基准）比 `$DSP`（更新欺骗星 M）早约 1s 到达。
若欺骗星沿用全局基准，会拿新 tow 配旧 M，位置先跳后回。因此：

- `SatelliteData.frameSimT0 / frameTow`：每颗星自己的"帧锚点"（M0 与 tow
  成对锚定的那一帧），`updateSimulation` 按逐星基准外推；
- `$ORB` 星随 applyOrbitFrame 锚定；`$DSP` 星随自己的 $DSP 帧锚定；
- 生成器保证 **$DSP 的 M 步长 = n(a)×快照 tow 步长**，锚点切换时惯性 M 与
  自转角同时连续，ECEF 位置无缝衔接。

### 10.3 逐帧 health（参与定位 = 当前仰角可见）

- 候选池 = 源文件并集内**全部**卫星（源帧 health 字段只是"第 0 分钟是否
  可见"的一次性标记，不得作为静态属性二次筛选——曾致可见数一天内 14~38
  疯摆；修正后稳定 32~42，均值 37）；
- 每帧 health = 0 当且仅当该星对石家庄仰角 ≥ 10°（`full_demo_generator`）；
- health 翻转时 `visibilityEpoch++` 并发 `satellitesVisibilityChanged`，
  QML 环/卫星 delegate 零重建切换显隐。

### 10.4 展示参照系 `inertialView`（默认惯性系）

| | 惯性系（默认） | 地固系（旧行为） |
|---|---|---|
| 轨道环 | 静止（周起始惯性系采样） | QML 侧转 `earthSpinDeg = -Ωe·tow` |
| 卫星渲染位置 | 惯性推进位置（不转） | ECEF（转 -Ωe·tow） |
| 地球+地面标记 | 转 `-earthSpinDeg`（=+Ωe·tow） | 静止 |
| 卫星经纬度/2D | 始终按 ECEF 计算（与显示模式无关） | 同左 |

物理背景：轨道面在惯性空间几乎不动；画面把地球"按住"（地固系）时，环相对
地球每天西移 360°——这不是 bug，是地球自转的镜像。两种模式转动总量相同。

### 10.5 回放节拍（orb_file_player）

- 按**快照块**发送（`$ORB/$TRJ/$MNT` 为块边界）：块内原子（M 与 tow 同批
  到达），块间匀速；各幕时间占比按行数分配（三幕演示 154/108/38 s）；
- 块目标时刻 = 逐块**累加**时间线（写成 `per*(idx+1)` 会让后幕瞬间倾泻，
  第三幕一闪而过）；
- C++ 侧 dayRate 估计抗 TCP 合包突发：到达间隔 <50ms 的帧不参与倍率学习，
  单样本瞬时倍率限幅在当前值 [1/4, 4] 倍。
